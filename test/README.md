# JianLing 套壳测试项目（test/）

这个目录是一个**可以直接被 JianLing 打包的 H5 内容目录**，用来一次性地测三端（Android / Windows / 静态站点）的壳能力。
以后要回归测试，不用再写临时页面，直接复用这里。

```
test/
├─ index.html    主自检页（环境信息 + 权限 + 媒体 + 存储 + 网络 + 下载 + 文件选择 + 交互 + 导航 + 报告）
├─ page2.html    二级页（返回键 / 导航栈 / 新窗口 / 长内容滚动）
├─ sample.txt    同源请求与下载用的样本文件
└─ README.md     本文件：打包步骤、人工测试清单、判定标准
```

自检页右上角有「复制报告」：所有结果会汇总成一段 JSON，复制发给我即可，比截图定位问题快得多。

## 一、怎么用它打包

JianLing（本项目）里新建/编辑项目，按下表填：

| 配置项 | 建议值 | 说明 |
| --- | --- | --- |
| 内容来源 | 本地目录 → 选择 `E:\Work\Tauri\AppShell\test` | 走 asset 模式，`START_URL` 变成 `https://appassets.androidplatform.net/assets/www/index.html` |
| 应用名 | 任意（推荐 `套壳自检`） | 只影响桌面图标/系统里的应用名，不再影响说明区标题 |
| 包名 / 版本 | 任意，如 `com.aspire.shelltest` / 1.0.0 | 换个包名方便和正式包共存 |
| 套壳权限 | 勾选：相机、麦克风、定位、通知、存储 | 少勾一项，对应权限测试就没有系统框可看 |
| 权限说明 | 每项都保持 `enabled=true`，标题/文案随便填 | **本轮改动重点**：只保留标题+文案，不再有「允许/拒绝」按钮 |
| 顶部操作栏 | 开启 | 用来测返回/前进/刷新与返回键行为 |
| 状态栏透明（边到边） | 保持开启（默认） | 工具栏灰底从屏幕最顶端开始；关掉工具栏时网页直接顶到屏幕最顶部 |
| 状态栏深色图标 | 开启 | 透明状态栏压在浅色页面上时图标才看得见 |
| 下拉刷新 | 开启 | 用来测手势与页面刷新 |
| 启动屏 | 先关；第二轮再开 | 开启动屏时容易盖住权限说明区，需要单独确认 |

打包出 APK 后：`adb install -r <apk>`；Windows 出 exe 直接双击。

## 二、Android 真机怎么测

> 你已连了真机，下面的命令在 `D:\Software\Development\SDK\android\platform-tools\` 下执行（`adb.exe`）。

```powershell
# 1) 确认设备
adb devices

# 2) 装包（同包名需先卸载，避免签名不一致）
adb uninstall com.aspire.shelltest
adb install -r .\套壳自检-1.0.0.apk

# 3) 把权限打回「未申请」，才能复现「申请前告知」
adb shell pm revoke com.aspire.shelltest android.permission.CAMERA
adb shell pm revoke com.aspire.shelltest android.permission.RECORD_AUDIO
adb shell pm revoke com.aspire.shelltest android.permission.ACCESS_FINE_LOCATION
# 通知权限(Android 13+)：
adb shell pm revoke com.aspire.shelltest android.permission.POST_NOTIFICATIONS

# 4) 启动并盯着壳日志
adb logcat -c
adb shell am start -n com.aspire.shelltest/.MainActivity
adb logcat | Select-String "MainActivity"

# 5) 看权限到底授没授
adb shell "dumpsys package com.aspire.shelltest | grep -E 'CAMERA:|RECORD_AUDIO:'"
```

### 权限说明区专项（本轮改动的验收点）

期望的完整流程（**不会在启动时自动申请**，只有页面真正用到该能力时才申请）：

1. 启动 App：不应出现任何权限框。
2. 在页面里点「申请相机 / 申请麦克风 / 申请定位」后，页面**顶部**浮出一块灰色卡片（带阴影、无白色底、无「权限申请」大标题）：
   - 卡片标题：就是配置里的「说明标题」原样显示（如填 `相机权限` 就显示 `相机权限`，不会自动加应用名）
   - 下方是项目里配的说明文案
   - **没有任何「允许 / 拒绝」按钮**
   - 位置：开着顶部操作栏时落在工具栏**下方**（不遮住返回/前进/刷新）；关掉工具栏时落在状态栏下方。
3. 约 0.7 秒后，弹出**系统**授权框（带有「仅本次允许 / 使用时允许」这类系统选项）。
4. 选「允许」→ 灰色卡片消失，页面拿到能力；选「拒绝」→ 卡片消失，该权限记入本地偏好（要重置见下）。
   在系统框里停留很久（几十秒）再点「允许」，卡片同样必须收起 —— 这是修复过的回归点。
5. **一次申请两个权限**：点「相机 + 麦克风（一次请求两个权限）」（内部是一次 `getUserMedia({audio:true, video:true})`）。
   仍然只有**一张**卡片，里面按「麦克风 / 相机」排两条说明，两条之间是一条分隔线；
   随后系统会连着弹两个授权框（相机、麦克风各一个），全部允许后该行记 PASS，值里显示 `轨道 2`。

「通知」不再走 WebView 的 `Notification.requestPermission()`（内核不支持，必然 FAIL），
改为调壳桥 `window.JianLing.requestPermission('notification')`：
Android 13+ 会先出说明卡片再弹系统框；13 以下没有通知运行时权限，页面直接记 PASS。

记录证据的两种方式：

```powershell
# A. 录屏 + 抽帧（最稳，能抓到一闪而过的说明区）
adb shell screenrecord --time-limit 6 /sdcard/perm.mp4
adb pull /sdcard/perm.mp4 .
ffmpeg -i perm.mp4 -vf fps=10 frames/f%03d.png

# B. 密集截图（设备端截，速度快）
adb shell "am start -n com.aspire.shelltest/.MainActivity; for i in 1 2 3 4 5 6; do screencap -p /sdcard/s$i.png; done"
```

重置「已拒绝」记忆（壳把 `runtime:<权限>` 存进了 SharedPreferences）：

```powershell
adb shell pm clear com.aspire.shelltest     # 等于清除应用数据，最干净
```

> 注意：本轮实现里，顶部说明区在拉起系统框前至少保留 **700ms**（`MainActivity.java` 的 `PERMISSION_NOTICE_MS`）。
> 原因：部分 ROM（含 MuMu 模拟器）会自动放行权限，系统框只闪一下，同步拉起会导致说明区根本来不及绘制，反而被判「未告知用途」。
> 真机上如果觉得等待偏长/偏短，改这个常量重新打包即可。

### 顶部栏 / 状态栏专项（「状态栏透明（边到边）」默认开启）

| 配置 | 期望 |
| --- | --- |
| 顶部操作栏 开 + 边到边 开 | 灰色工具栏背景**从屏幕最顶端一路铺到状态栏**，状态栏图标压在灰条上；网页从工具栏下沿开始 |
| 顶部操作栏 关 + 边到边 开 | 没有工具栏时，网页**从屏幕最顶部开始渲染**（状态栏透明压在页面上），页面需自己留出状态栏高度 |
| 顶部操作栏 开/关 + 边到边 关 | 状态栏用「状态栏颜色」绘制，内容让出状态栏高度（旧行为） |

判定：状态栏图标能不能看清取决于「状态栏深色图标」开关 —— 透明状态栏 + 浅色页面必须开深色图标。
若看到状态栏区域出现一条灰纱，说明系统对比度蒙层没关掉（`setStatusBarContrastEnforced(false)`），可直接报给我。

## 三、人工测试清单

三端都适用的项在 `index.html` 里点按钮即可；**页面点不到的能力**列在下面，需要人工按步骤确认。

### 1) Android 壳

| 检查项 | 操作 | 判定 |
| --- | --- | --- |
| 权限说明区 | 清数据后首启，按上面「专项」步骤 | 说明区先出现、系统框后出现、无自定义按钮 |
| 相机/麦克风实采 | 点「申请」「启动」，再点「停止」 | 预览有画面、停止后指示灯灭 |
| 定位 | 点「申请定位」 | 有系统框；允许后能拿到经纬度 |
| 通知 | 点「通知 → 申请」 | Android 13+：说明卡片 + 系统框；13 以下：页面直接 PASS |
| 剪贴板读写 | 点读取/写入，去微信粘贴 | 能读到、能粘贴出 `jianling-clip-*` |
| 文件选择 | 点选择文件 / 拍照 | 起系统选择器；拍照能回传文件 |
| 下载 | 点「下载」 | 文件进系统下载目录、通知栏可见 |
| 外链 | 点「外链」 | 起系统浏览器（或按配置在内置窗口） |
| 返回键 | 进 page2 后按返回；再在首页连按两次 | 第一次回上一页；首页双击退出（若开启）；开启「禁止返回键退出应用」时首页按返回无反应、应用不退出 |
| 视频全屏 | 点「video 全屏」，按返回 | 只退出全屏，不退出应用 |
| 下拉刷新 | 在 page2 下拉 | 出现刷新指示、页面重载 |
| 状态栏/全屏 | 打包配置切换后重装 | 与配置一致：边到边时工具栏铺满状态栏、无工具栏时网页顶到屏幕顶端；关闭边到边时状态栏用配置色 |

| 启动屏 | 开启启动屏打包 | 启动屏 → 页面；说明区不被永久遮挡 |
| 本地服务器代理 | 配 `/api` 转发规则，页面点 fetch 同源 | `status=200`，不是 404/500 |
| asset 模式缓存 | 断网后重开 | 页面仍能打开（本地内容） |

## 四、我这边的自动化边界（供参考）

- **能自动跑**：页面自身的全部按钮逻辑（环境、存储、网络、下载触发、文件选择触发、媒体 API 调用结果），以及 APK 安装/启动/权限授予状态（`adb` + `dumpsys`）。
- **只能靠抓帧确认**：权限说明区的出现顺序与停留时长（`screenrecord` + `ffmpeg` 抽帧）。
- **必须人工确认**：系统授权框的样式与选项、真实摄像头/麦克风画面、通知栏、系统下载目录、系统浏览器跳转、Windows 窗口/托盘/单实例/自启动/安装包、开机行为。
- **模拟器不可靠**：MuMu 会自动放行运行时权限，系统框几乎不可见，因此「说明区是否可见」必须在真机或录屏逐帧里看。

## 五、已知问题 / 待确认

- 权限说明区是「进入页面顶部浮动」的灰色卡片（无白底、无大标题），暂不支持自定义颜色/圆角。
- 权限被拒后会**永久跳过**该权限（存 `runtime:<权限>=denied`）。如果希望每次启动都重新申请，需要调整 `MainActivity._requestNextRuntimePermission()` 里的 `remembered` 逻辑。
- 说明区最短展示时长 `PERMISSION_NOTICE_MS = 700`，是否合适需要真机手感确认。
